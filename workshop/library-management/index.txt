1b:Te6b,# Editorial: Library management

## Requirements
Functional: register books (with copy counts) and members, borrow, return, search by author. Hidden until asked: a three-book limit, one copy of a title per member, and specific statuses for every failure (a failed call changes nothing). Non-goals: persistence, UI, due dates (but keep them cheap to add).

**Change Storm 1, membership tiers:** Premium members may hold 5 books, Basic members 3; staff can change a tier; demoting a member who holds more than the new limit is refused (`LimitReached`, nothing changes). It is revealable by asking whether different kinds of members will ever get different rules.

## Reference design
- `Catalog` owns books and their shelf counts; it is the only place a count changes.
- `Member` owns its id, name and the set of book ids it holds.
- `LoanPolicy` (abstract) answers "may this member borrow one more?"; `FixedLimitPolicy(3)` is the rule here.
- `LibraryService` implements `lib::Library`. It validates, asks the policy, then mutates: check everything first, change state last.

**Storm 1 in the reference:** a new `TierLimitPolicy` (one class) replaces `FixedLimitPolicy` in the factory; `Member` gains a tier; the service gains `setTier` and `tierOf` via the new `TieredLibrary` interface. `borrow()` is untouched, which is the point: the seam existed before the requirement did. The honest cost: `Member`, `LibraryService` and the factory still change, so the OCP score is high but not 100%.

Ownership: the service owns catalog, members and a `unique_ptr<LoanPolicy>`. No raw `new`, no shared state outside the service.

## Alternatives
- **One big `Library` class with two maps** is the fastest to type and passes the base tests. It is also where the bugs in `bad/` come from, and it turns every later requirement into an edit of the same method. Fine for a 20-minute warm-up, weak in a 90-minute round.
- **A `Loan` entity** (member, book, date) instead of a set of ids is better the moment due dates arrive; for the base phase it is one class too many. Say so out loud and move on.
- **A per-title `Book` object holding its own copy count** is reasonable too; the Catalog-owns-counts version keeps the invariant in one place.

## Trade-offs
Tiers as an enum on `Member` plus a limit table is the smallest thing that works. If tiers later carry behaviour beyond a number (loan length, fines, reservations), promote the tier to a polymorphic `MembershipPlan` object; do it when the second behaviour appears, not before.

Policy as a class costs one interface and one file; it buys the Open/Closed seam where the interviewer is most likely to push. A constant is cheaper and correct if limits never vary. Status codes instead of exceptions keep call sites explicit and work in the browser toolchain (no exception runtime); the cost is that a caller can ignore a result, which `[[nodiscard]]` on the status type would catch in a real codebase.

## What breaks at 10x
At 10x the data (tens of thousands of books) the maps are still fine and author search becomes the first scan worth indexing (`unordered_map<author, set<id>>`). At 10x the callers (concurrent staff terminals) the lack of locking becomes the issue: see the follow-up on thread safety.

## Level signals
- **SDE2:** correct behaviour, clear class split, asks about limits and duplicates, tests its own edge cases.
- **Senior:** names the extension seam (policy), validates before mutating, discusses concurrency and due dates unprompted, keeps the design small.
- **Staff:** frames what is likely to change and what is not, ties the in-memory design to the multi-branch future, and states what they deliberately did not build.

// Owns the books and their shelf counts. The only place a count changes.
class Catalog {
 public:
  bool add(const std::string& id, const std::string& title, const std::string& author, int copies) {
    return books_.emplace(id, Book{title, author, copies}).second;
  }
  bool contains(const std::string& id) const { return books_.count(id) != 0; }
  int available(const std::string& id) const {
    auto it = books_.find(id);
    return it == books_.end() ? -1 : it->second.onShelf;
  }
  // Precondition: available(id) > 0.
  void takeCopy(const std::string& id) { --books_.at(id).onShelf; }
  void returnCopy(const std::string& id) { ++books_.at(id).onShelf; }

  std::vector<std::string> findByAuthor(const std::string& author) const {
    std::vector<std::string> ids;
    for (const auto& [id, book] : books_) {
      if (book.author == author) ids.push_back(id);  // std::map iterates in id order
    }
    return ids;
  }

 private:
  struct Book {
    std::string title;
    std::string author;
    int onShelf;
  };
  std::map<std::string, Book> books_;
};

using lib::Status;

Status LibraryService::addBook(const std::string& bookId, const std::string& title, const std::string& author, int copies) {
  return catalog_.add(bookId, title, author, copies) ? Status::Ok : Status::DuplicateId;
}

Status LibraryService::addMember(const std::string& memberId, const std::string& name) {
  return members_.emplace(memberId, Member(memberId, name)).second ? Status::Ok : Status::DuplicateId;
}

Status LibraryService::borrow(const std::string& memberId, const std::string& bookId) {
  auto m = members_.find(memberId);
  if (m == members_.end()) return Status::NoSuchMember;
  if (!catalog_.contains(bookId)) return Status::NoSuchBook;
  Member& member = m->second;
  if (member.holds(bookId)) return Status::AlreadyBorrowed;
  if (catalog_.available(bookId) == 0) return Status::NoCopiesAvailable;
  if (!policy_->mayBorrow(member)) return Status::LimitReached;
  catalog_.takeCopy(bookId);
  member.addLoan(bookId);
  return Status::Ok;
}

Status LibraryService::giveBack(const std::string& memberId, const std::string& bookId) {
  auto m = members_.find(memberId);
  if (m == members_.end()) return Status::NoSuchMember;
  if (!catalog_.contains(bookId)) return Status::NoSuchBook;
  if (!m->second.holds(bookId)) return Status::NotBorrowed;
  m->second.removeLoan(bookId);
  catalog_.returnCopy(bookId);
  return Status::Ok;
}

std::vector<std::string> LibraryService::loansOf(const std::string& memberId) const {
  auto m = members_.find(memberId);
  return m == members_.end() ? std::vector<std::string>{} : m->second.loans();
}

Status LibraryService::setTier(const std::string& memberId, lib::Tier tier) {
  auto m = members_.find(memberId);
  if (m == members_.end()) return Status::NoSuchMember;
  // Demotion must not leave a member holding more than the new tier allows.
  if (m->second.loanCount() > policy_->limitFor(tier)) return Status::LimitReached;
  m->second.setTier(tier);
  return Status::Ok;
}

lib::Tier LibraryService::tierOf(const std::string& memberId) const {
  auto m = members_.find(memberId);
  return m == members_.end() ? lib::Tier::Basic : m->second.tier();
}

  return std::make_unique<LibraryService>(std::make_unique<TierLimitPolicy>(3, 5));
}

std::unique_ptr<lib::Library> lib::makeLibrary() { return lib::makeTieredLibrary(); }
