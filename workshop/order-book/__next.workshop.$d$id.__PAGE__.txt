13:T640,# Order book: the matching engine of an exchange, one instrument

You are building the heart of a small exchange: no network, no screen, no money, only the book. Traders send **limit orders** (buy or sell, a price, a quantity). The book trades them against orders that are already waiting, and keeps whatever is left so that later orders can trade with it. The same few rules run every stock exchange, so every candidate is expected to know them cold.

What you know so far:

- A buy order wants to pay at most its limit; a sell order wants to receive at least its limit. Prices and quantities are whole numbers.
- Orders that cannot trade yet wait in the book, buys on one side and sells on the other.
- A new order trades with the waiting orders on the other side. It goes to the best price first, and among equal prices to whoever came first.
- A waiting order can be cancelled. Everything is single-threaded and deterministic, so every test can replay an exact sequence.

Your task: design and implement it behind the `book::Book` interface in `api.h` (`makeBook()` is yours to define). The hidden tests call only that interface. Ask the interviewer questions first: "at which price does a trade happen?", "what does an order that is only partly filled do?", "what is the best price on each side?", "can an id come back?" and "what does each call answer, and in which order does it check?" are where first drafts go wrong. Expect a change request for how long an order may wait (immediate-or-cancel, fill-or-kill) once the basics work, and then one for amending an order that is already resting.
14:T1c73,# Editorial: An order book with price-time priority, time in force and amends

## Requirements
Functional: a `Book` for one instrument that accepts limit orders (`submit`), cancels resting ones (`cancel`) and answers `remaining`, `bestBid`, `bestAsk`, `depthAt`, `restingCount`. Then time in force (immediate-or-cancel, fill-or-kill) and then `amend`.

Hidden in the brief and revealed by good questions: the ranges (ids from 1, prices and quantities with both ends inclusive) and the check order (InvalidOrder before DuplicateId; a refusal changes nothing, not even the caller's vector); that an id is spent forever by any accepted order; that a trade happens at the WAITING order's price; best price first (lowest sell, highest buy) then earliest arrival; that the remainder rests at its own limit and a partly filled order keeps its place; that cancel needs a resting order and leaves the others in place; and that the top of book is the total at the best price.

**Change Storm 1, time in force:** Ioc never rests; Fok trades everything or leaves the book untouched, so it needs a question the book can answer without changing. **Change Storm 2, amend:** the same price with a smaller or equal size keeps the place; anything else is a new arrival with the old id that trades at once if it crosses.

## Reference design
Seven small classes, each with one reason to change.

- **`Order`:** id, side, price and what is still unfilled. Only the unfilled quantity changes.
- **`HalfBook`:** one side as an ordered map from price to a `std::list` queue, with the best price always first (sells are keyed by price, buys by its negation, so `begin()` is the best on both sides). It can add, remove by position, sum a level, and answer `availableFor(limit)` as a pure query. It knows nothing about trading.
- **`RestingIndex` and `IdLedger`:** the first maps an id to its side, price and list position so cancel, amend and `remaining` are O(1) lookups; the second is the set of every id ever accepted. They answer different questions ('where is it?' versus 'was it ever used?'), which is why a filled order is in the ledger and not in the index.
- **`Matcher`:** the one rule of the market. While the taker has quantity and the best opposite price is acceptable, trade with the oldest order at that price, at its price, and retire a maker that is fully filled. `available(order)` is the read-only twin used by fill-or-kill.
- **`Disposition` (Strategy):** `GoodTillCancelled`, `ImmediateOrCancel`, `FillOrKill` each answer two small questions: may this order start trading, and does the remainder rest? The enum maps to an object in one place.
- **`OrderRules`:** the ranges, in one class.
- **`BookImpl` (Facade):** validates, records the id, and sends the order down one private path, `enter`, that previews, matches and rests. An amend that loses its place calls `enter` as well, so a crossing amend trades exactly like a new order.

The storms edited nothing that existed: storm 1 added two small classes and a map entry, storm 2 added one method that reuses `enter`.

## Alternatives
- **Sorted vector of levels (or a dense array indexed by tick):** faster for the real hot path (see 10x), simpler to reason about for a small tick range, but O(L) inserts as a vector and a memory cost as an array. The map is the right interview default; naming the array is a senior signal.
- **One map for both sides with a comparator flag:** shorter, but every use then has to remember which direction 'best' means. Two `HalfBook` objects make the direction a property of the object, and the matcher never branches on it.
- **A priority queue of orders:** gives best price but not FIFO within a price unless every order carries a sequence number, and cancelling from the middle needs lazy deletion. It works (heap + sequence + tombstones) and is a common first draft; the ordered map is cleaner when cancels are frequent.
- **Time in force as flags and `if`s in `submit`:** the shortest first draft and the one the storm punishes: every new kind edits the same function. Small policy classes put each rule in one place.
- **Amend as 'cancel then submit' by the caller:** simple, but it loses atomicity (another order can arrive between the two calls) and the in-place reduction cannot be expressed. The book must own the amend.

## Trade-offs
- **Ordered map versus arrays.** `std::map<int, std::list<Order>>` allocates per order and per level and chases pointers. It is easy to get right and fast enough for an interview, and the wrong choice for a production engine with a microsecond budget.
- **Keeping the book honest on refusals.** Every check happens before the first change, so a refused call leaves nothing behind. That is why `fills.clear()` comes after the validation and why a refused amend does not touch the caller's vector.
- **Preview then commit versus rollback.** Fok asks a pure question first. It costs a second walk over the levels, and it is the only design where an observer never sees a half-trade.
- **One class with many methods versus a facade over parts.** The facade has nine methods and no rule of its own. The cost is that the parts hand data to each other through small interfaces; the gain is that each of them is tested by the same random model without caring which one broke.
- **Statuses instead of exceptions.** The judge builds without exceptions and the caller meets refusals in normal use, so a documented check order is a better contract.

## What breaks at 10x
- **Throughput:** the map and list allocate on every order. Use an arena of orders addressed by index, a dense array of price levels with a bitmap to find the best one, and an intrusive queue per level. Pin one thread to the instrument.
- **Many instruments:** one book per instrument, sharded by symbol across threads; the books share nothing. Cross-instrument risk checks go in front of the book, not inside it.
- **Recovery:** the book is a function of an input log. Persist and sequence the log, snapshot periodically, replay the tail, and let a standby follow the same log.
- **Fairness and audit:** assign a sequence number to every event; time priority is then exactly 'lower sequence first' and can be proved from the log.
- **More order types:** market orders are Ioc with an extreme price; stops wait outside the book and enter through `enter`; icebergs make queue entries refreshable. None of them changes `Matcher`.

## Level signals
- **SDE II:** a working book: a map per side, a queue per price, best price first, trades at the resting price, cancel by scanning if needed. Passes the base tests; matching probably lives inside the book class.
- **Senior:** one place for the matching rule, a side that hides which direction is 'best', an id index for O(1) cancel, a separate ledger for used ids, fill-or-kill decided by a pure preview, time in force as small policies, and an amend that reuses the entry path. States when the priority rule is fair and why reducing keeps the place.
- **Staff:** talks about the sequenced input log, deterministic replay and failover before being asked, the arena and tick-array layout for the hot path, the model-based test with invariants, risk checks in front of the book, and what to freeze in the contract (check order, fill shape, id rule).

#include <memory>
#include <vector>

namespace book {

enum class Side { Buy, Sell };

enum class Status {
  Ok,
  InvalidOrder,  // id, price or quantity outside the documented range
  DuplicateId,   // the id was used before, by an order in any state
  UnknownOrder,  // no RESTING order has that id
};

// One trade. The price is always the RESTING (maker) order's price, never the incoming order's limit.
struct Fill {
  int takerId;  // the incoming order
  int makerId;  // the order that was already resting
  int price;
  int quantity;
};
inline bool operator==(const Fill& a, const Fill& b) {
  return a.takerId == b.takerId && a.makerId == b.makerId && a.price == b.price && a.quantity == b.quantity;
}

constexpr int kMaxPrice = 100000;
constexpr int kMaxQuantity = 1000000;

// A limit-order book for ONE instrument, in integer ticks, matched by PRICE-TIME PRIORITY.
//
// ORDERS. An order has an id (1 or more), a side, a limit price (1..kMaxPrice) and a quantity (1..kMaxQuantity). Ids are
// never reused: an id that was ever accepted is a DuplicateId forever, even after the order was filled or cancelled.
//
// SUBMIT. submit() checks InvalidOrder first, then DuplicateId; a refused call changes nothing and leaves `fills` alone. On
// Ok, `fills` is replaced by the trades this order caused, in the order they happened (possibly none). A BUY order trades
// with resting SELL orders priced at or below its limit; a SELL order trades with resting BUY orders priced at or above it.
// It always takes the BEST price first (lowest sell, highest buy), and among orders at the same price the one that arrived
// FIRST. Each trade is min(remaining of both) at the resting order's price. Whatever is left of the incoming order then
// rests in the book at its limit, behind the orders already at that price. An order never trades with its own side.
//
// CANCEL. cancel(id) removes a resting order: UnknownOrder when no resting order has that id (never accepted, filled in
// full, or already cancelled). The orders behind it keep their places.
//
// QUERIES (never change anything). remaining() is the unfilled quantity of a RESTING order, UnknownOrder otherwise (the
// out-parameter is touched only on Ok). bestBid() and bestAsk() give the best price on that side and the TOTAL quantity
// resting at that price, and answer false when the side is empty. depthAt() is the total resting quantity of a side at one
// price (0 when none), and restingCount() is the number of resting orders.
class Book {
 public:
  virtual ~Book() = default;

  virtual Status submit(int id, Side side, int price, int quantity, std::vector<Fill>& fills) = 0;
  virtual Status cancel(int id) = 0;

  virtual Status remaining(int id, int& out) const = 0;
  virtual bool bestBid(int& price, int& quantity) const = 0;
  virtual bool bestAsk(int& price, int& quantity) const = 0;
  virtual int depthAt(Side side, int price) const = 0;
  virtual int restingCount() const = 0;
};

std::unique_ptr<Book> makeBook();

}  // namespace book

// An independent model: a list of orders and a linear search for the best counterparty each time.
struct ModelOrder {
  int id;
  Side side;
  int price;
  int rem;
  long seq;
};

class ModelBook {
 public:
  std::vector<Fill> submit(int id, Side side, int price, int qty) {
    std::vector<Fill> fills;
    ModelOrder taker{id, side, price, qty, seq_++};
    while (taker.rem > 0) {
      int best = -1;
      for (int i = 0; i < static_cast<int>(orders_.size()); ++i) {
        const ModelOrder& o = orders_[i];
        if (o.side == side) continue;
        const bool crosses = side == B ? o.price <= price : o.price >= price;
        if (!crosses) continue;
        if (best < 0 || better(o, orders_[best], side)) best = i;
      }
      if (best < 0) break;
      ModelOrder& maker = orders_[best];
      const int traded = std::min(taker.rem, maker.rem);
      fills.push_back(Fill{id, maker.id, maker.price, traded});
      taker.rem -= traded;
      maker.rem -= traded;
      if (maker.rem == 0) orders_.erase(orders_.begin() + best);
    }
    if (taker.rem > 0) orders_.push_back(taker);
    return fills;
  }
  bool cancel(int id) {
    for (std::size_t i = 0; i < orders_.size(); ++i) {
      if (orders_[i].id == id) {
        orders_.erase(orders_.begin() + static_cast<long>(i));
        return true;
      }
    }
    return false;
  }
  int depth(Side side, int price) const {
    int sum = 0;
    for (const auto& o : orders_) sum += (o.side == side && o.price == price) ? o.rem : 0;
    return sum;
  }
  int best(Side side) const {
    int p = 0;
    for (const auto& o : orders_) {
      if (o.side != side) continue;
      if (p == 0 || (side == B ? o.price > p : o.price < p)) p = o.price;
    }
    return p;
  }
  int count() const { return static_cast<int>(orders_.size()); }
  int remaining(int id) const {
    for (const auto& o : orders_) {
      if (o.id == id) return o.rem;
    }
    return -1;
  }

    if (handle == nullptr) return book::Status::UnknownOrder;
    fills.clear();

    Order order(id, side, newPrice, newQuantity);
    enter(order, Dispositions::of(book::TimeInForce::Gtc), fills);
    return book::Status::Ok;
  }

  book::Status remaining(int id, int& out) const override {
    const RestingIndex::Handle* handle = index_.find(id);
    if (handle == nullptr) return book::Status::UnknownOrder;
    out = handle->position->remaining();
    return book::Status::Ok;
  }

  bool bestAsk(int& price, int& quantity) const override { return sides_.own(book::Side::Sell).best(price, quantity); }
  int depthAt(book::Side side, int price) const override { return sides_.own(side).depthAt(price); }

// Which way "better" points on one side, and how a price becomes a map key so that the best price sorts first: sells by
// price, buys by its negation.
class PriceOrder {
 public:
  explicit PriceOrder(book::Side side) : side_(side) {}

  int keyOf(int price) const { return side_ == book::Side::Sell ? price : -price; }
  int priceOf(int key) const { return side_ == book::Side::Sell ? key : -key; }
  // Would an incoming order with this limit trade at `price` on this side?
  bool acceptable(int price, int limit) const { return side_ == book::Side::Sell ? price <= limit : price >= limit; }

 private:
  book::Side side_;
};

// All the resting orders of ONE side, grouped by price, each price a queue in arrival order. The map key is arranged so that
// the BEST price is always first: sells by price, buys by negated price. Nothing here knows how orders trade.
class HalfBook {
 public:
  using Queue = std::list<Order>;
  using Position = Queue::iterator;

  explicit HalfBook(book::Side side) : order_(side) {}

  bool empty() const { return levels_.empty(); }
  int bestPrice() const { return order_.priceOf(levels_.begin()->first); }
  Order& oldestAtBest() { return levels_.begin()->second.front(); }

  // True when an incoming order with this limit would trade with the best price here.
  bool crossedBy(int limit) const {
    return !empty() && order_.acceptable(bestPrice(), limit);
  }

  Position add(const Order& order) {
    Queue& queue = levels_[order_.keyOf(order.price())];
    queue.push_back(order);
    return std::prev(queue.end());
  }

  void remove(int price, Position position) {
    const auto level = levels_.find(order_.keyOf(price));
    level->second.erase(position);
    if (level->second.empty()) levels_.erase(level);
  }

  int depthAt(int price) const {
    const auto level = levels_.find(order_.keyOf(price));
    return level == levels_.end() ? 0 : total(level->second);
  }

  bool best(int& price, int& quantity) const {
    if (empty()) return false;
    price = bestPrice();
    quantity = total(levels_.begin()->second);
    return true;
  }

  // Quantity an incoming order with this limit could trade with, best price first, without changing anything.
  int availableFor(int limit) const {
    int sum = 0;
    for (const auto& [key, queue] : levels_) {
      if (!order_.acceptable(order_.priceOf(key), limit)) break;
      sum += total(queue);
    }
    return sum;
  }

 private:
  static int total(const Queue& queue) {
    int sum = 0;
    for (const Order& order : queue) sum += order.remaining();
    return sum;
  }

  PriceOrder order_;
  std::map<int, Queue> levels_;
};

// The two sides of the book and the one rule that moves orders between them: price-time priority.
class Sides {
 public:
  Sides() : bids_(book::Side::Buy), asks_(book::Side::Sell) {}

  HalfBook& own(book::Side side) { return side == book::Side::Buy ? bids_ : asks_; }
  const HalfBook& own(book::Side side) const { return side == book::Side::Buy ? bids_ : asks_; }
  HalfBook& other(book::Side side) { return own(side == book::Side::Buy ? book::Side::Sell : book::Side::Buy); }
  const HalfBook& other(book::Side side) const {
    return own(side == book::Side::Buy ? book::Side::Sell : book::Side::Buy);
  }

 private:
  HalfBook bids_;
  HalfBook asks_;
};

class Matcher {
 public:
  Matcher(Sides& sides, RestingIndex& index) : sides_(sides), index_(index) {}

  // Trades `taker` against the opposite side while the best price is acceptable, oldest order first, at the maker's price.
  void match(Order& taker, std::vector<book::Fill>& fills) {
    HalfBook& opposite = sides_.other(taker.side());
    while (!taker.done() && opposite.crossedBy(taker.price())) {
      Order& maker = opposite.oldestAtBest();
      const int traded = std::min(taker.remaining(), maker.remaining());
      fills.push_back(book::Fill{taker.id(), maker.id(), maker.price(), traded});
      taker.fill(traded);
      maker.fill(traded);
      if (maker.done()) retire(opposite, maker);
    }
  }

  // What an order like this could trade right now. Pure: nothing moves.
  int available(const Order& taker) const { return sides_.other(taker.side()).availableFor(taker.price()); }

 private:
  void retire(HalfBook& side, const Order& maker) {
    const RestingIndex::Handle* handle = index_.find(maker.id());
    const int id = maker.id();
    side.remove(handle->price, handle->position);
    index_.forget(id);
  }

  Sides& sides_;
  RestingIndex& index_;
};
