1b:T557,# Stack Overflow-lite

You are building the core of a small question-and-answer site: the part that decides who has asked what, who has voted how, and, above all, **how much reputation everybody has**. There is no web page and no database: the tests call one interface and everything is in memory.

What you know so far:

- Users sign up with a name. A new user has reputation 1.
- A user asks a question and any user can answer it.
- Other users vote a post up or down.
- The person who asked can accept one answer as the best.
- Votes and acceptances change the reputation of the people involved.
- You can ask for a user's reputation, a post's score and a question's answers, best first.

Your task: design and implement it behind the `qa::Site` interface in `api.h`. The hidden tests call only that interface. Ask the interviewer before you write anything: "how many points is each thing worth?", "can I vote on my own post?", "what happens when I change my mind about a vote?", "what is the lowest reputation can go?" and "which error wins when several things are wrong?" are where first drafts go wrong. Expect two follow-up requests once you are done: a daily limit on what votes can earn, and letting authors delete their posts. Both are much easier if reputation is something you can recompute from what is true now, rather than a number you keep adjusting.

## Requirements
Functional: add users; ask a question; answer it; vote a post up or down (one vote per voter per post, switching replaces, `unvote` takes it back); accept an answer; read a user's reputation, a post's score and a question's ordered answers. Then a daily cap on what upvotes can earn, and then authors deleting their posts.

Hidden in the brief and revealed by good questions: the points table (+5 and +10 for upvotes, -2 for a downvote, -1 more for the voter who downvotes an answer, +15 and +2 for an acceptance and nothing for accepting your own answer); that reputation is derived and floored at 1 on the **total**; the voting rules (self vote, a downvote needs reputation 15, `AlreadyVoted` versus switching); the order of the statuses; that a question has at most one accepted answer and moving it moves the points; and the order of `answers`.

**Change Storm 1, a daily cap:** per user and day, upvote points count at most the cap; penalties and acceptances are uncapped; a switched vote belongs to the day it was cast; taking a vote back can lift a day back under the cap.

**Change Storm 2, deleting posts:** only the author may delete; a question takes its answers with it; every vote, acceptance and point that depended on a deleted post disappears; ids are free and clean again; votes the author cast elsewhere stay.

## Reference design
`SiteImpl` is a thin facade: it checks the documented rules in order and writes to the collaborators. It does no point arithmetic. `PostBoard` owns the live posts (kind, author, parent, creation sequence). `VoteBook` keeps every vote that stands, one per voter per post, with its day. `AcceptBook` maps a question to its accepted answer. These three hold **facts** and nothing else.

`Ledger` turns the facts into `ReputationEvent`s for one user (an upvote pays the author by kind, a downvote charges the author and, on an answer, the voter; an acceptance pays the answer's author and the asker unless they are the same person). A `ReputationPolicy` adds the events up: `PlainPolicy` sums them, `DailyCapPolicy` limits the capped events per day. The floor is applied once, to the total. Reputation is therefore never stored, and every undo is just 'remove a fact'.

Storm 1 added the clock, one new policy class and a factory; the ledger, the books and the existing policy were not edited. Storm 2 added `PostRemover`, which removes a post with its votes and acceptance (and a question's answers) in one place, and one method to the facade. Because reputation is derived, nothing needed correcting after a delete. `AnswerLister` builds the ordered list from the three books.

## Alternatives
- **Stored balances updated by each action.** Reading is O(1) and the code is short at first. Every undo (unvote, switch, move acceptance, delete) needs a mirror-image update, the floor makes some of those wrong, and the cap makes every later vote depend on earlier ones. Fast to write, slow to keep correct.
- **Event log with replay.** Store each reward and reversal as an event and replay for reputation. Equivalent to this design when the reversals are modelled; the facts-first version avoids having to invent compensating events and keeps the data smaller.
- **Per-user event lists maintained on every write.** An index from user to the votes and acceptances that affect them; reputation reads only those. A good optimisation of the reference (the 10x section), but it must be updated in the same places the books are, so it is a second structure that can drift.
- **Soft-deleted posts.** Keep a flag and filter in every reader. Keeps history for moderation, at the price of every reader remembering the flag.
- **One class with `if (kind == ...)` for points.** A fine first draft; the cap and the delete each add branches to the same methods.

## Trade-offs
- **Derive instead of store.** Every rule that removes something becomes trivial and exact; reads cost a pass over the facts (here a scan of all votes) until a cache is added.
- **Policy as a Strategy over events.** The cap is rewritten from events every time, so it stays right under undo. The cost is one small interface and the discipline that events carry what the policy needs (day, whether capped).
- **Hard delete.** Exact numbers and clean ids, but no audit history; real sites soft-delete underneath.
- **The privilege check reads current reputation.** Correct and simple, but it ties a vote to a derived number, which is a race in a concurrent system.
- **Ordering rule for statuses.** A fixed, documented order is the only thing a caller can rely on when several things are wrong at once.

## What breaks at 10x
- **Reputation reads:** `reputation()` walks every vote and acceptance. Keep a per-user index of the events that affect them, or a cache invalidated for the users a write touches (author, voter, asker).
- **Answers:** `PostBoard::answersOf` scans every post. Keep a list of answers per question.
- **Votes:** the `VoteBook` is a nested map by post; fine to millions of votes in memory, then it belongs in a table keyed by (post, voter) with an index by user.
- **Threads:** the downvote privilege check and the write must be atomic; one writer per user or a transaction with the check as a condition.
- **Scale-out:** the facts are an append-friendly stream; derive reputation in a stream processor and serve it from a cache, with a periodic full recompute as the audit.
- **Abuse:** voting rings are a policy problem on the same facts, handled by offline detection and compensating reversals.

## Level signals
- **SDE II:** the points table right, the statuses in a sensible order with a refused call changing nothing, a vote switch that replaces the old effects, and an accepted answer that moves cleanly. Names and classes that separate posts, votes and the rules.
- **Senior:** reputation derived from facts (and the floor on the total), a clean undo for every action, the cap as a policy rather than a branch, and a delete that removes the post and everything hanging on it in one place. Tests that compare against a plain model.
- **Staff:** frames derived versus stored versus event-sourced reputation and what each does under undo and scale, raises the privilege race, caching and invalidation sets, streaming derivation with reconciliation, soft versus hard delete for audit, and abuse detection (voting rings) as policies over the same facts, naming what each choice gives up.

// Public API for the Stack Overflow-lite problem. The hidden tests only use what is declared here.
// You implement qa::makeSite() (in any of your .cpp files); everything behind it is your design.
#include <memory>
#include <string>
#include <vector>

namespace qa {

enum class Status {
  Ok,
  InvalidInput,     // a name or id that is empty or longer than 32 characters, or a day outside the allowed range
  DuplicateUser,    // a user with this name already exists
  UnknownUser,      // no user with this name
  DuplicatePost,    // a live post (question or answer) already has this id
  UnknownPost,      // no live post with this id (or, for answer(), no live QUESTION with this id)
  SelfVote,         // voting on your own post
  LowReputation,    // a downvote needs reputation kMinDownvoteReputation
  AlreadyVoted,     // the voter already has this very vote on the post
  NoVote,           // unvote with no vote to take back
  WrongKind,        // accept() on a question
  NotAuthor,        // accept(): not the asker; remove(): not the author of the post
  AlreadyAccepted,  // this answer is already the accepted one
};

constexpr int kMinDownvoteReputation = 15;  // reputation needed to downvote
constexpr int kMaxDay = 1000000;            // (storm 1) days are 0..kMaxDay

struct AnswerInfo {
  std::string id;
  std::string author;
  int score = 0;       // upvotes minus downvotes
  bool accepted = false;
};

// A small question-and-answer site. Users ask questions and answer them; other users vote on posts and the asker accepts
// one answer. Everything the site pays out is REPUTATION, and reputation is the heart of this problem.
// Single-threaded and deterministic. A refused call changes nothing.
//
// addUser(name): the name is 1 to 32 characters (InvalidInput), then DuplicateUser. A new user has reputation 1.
// ask(id, author): InvalidInput (id empty or longer than 32 characters), UnknownUser, DuplicatePost.
// answer(id, question, author): InvalidInput, UnknownUser, UnknownPost (no live QUESTION called `question`), DuplicatePost.
//   Questions and answers share one id space. A user may answer their own question.
//
// vote(voter, post, up): CHECK ORDER UnknownUser, UnknownPost, SelfVote (the voter wrote the post), LowReputation (a
// downvote needs the voter's CURRENT reputation >= kMinDownvoteReputation; upvotes need none), AlreadyVoted (the voter
// already has this same vote on the post). A voter has at most one vote per post: voting the opposite way REPLACES the old
// vote, as if it had been taken back first.
// unvote(voter, post): UnknownUser, UnknownPost, NoVote. Takes the vote back, with every effect it had.
//
// Reputation points (the author of the post is the one who is paid):
//   upvote on a question +5, upvote on an answer +10, downvote on any post -2 (and the VOTER pays 1 for downvoting an
//   ANSWER, nothing for a question).
//   accept(user, answer): UnknownUser, UnknownPost, WrongKind (it is a question), NotAuthor (only the asker of that
//   answer's question may accept), AlreadyAccepted. The answer's author gets +15 and the asker +2, but when both are the
//   same person nobody is paid. A question has at most ONE accepted answer: accepting another answer moves the acceptance,
//   and the old answer's +15 and the asker's +2 for it are gone.
//
// reputation(user) is DERIVED from what is currently true: 1 plus the points of every vote and acceptance that currently
// stands, but never below 1 (the floor applies to the total, not to each step). An unknown user has reputation 0.
// score(post) is upvotes minus downvotes (0 for an unknown post).
// answers(question): every live answer, the accepted one first, then higher score first, then the older answer first.
//   Empty for an unknown post or for an answer.
class Site {
 public:
  virtual ~Site() = default;
  virtual Status addUser(const std::string& name) = 0;
  virtual Status ask(const std::string& id, const std::string& author) = 0;
  virtual Status answer(const std::string& id, const std::string& question, const std::string& author) = 0;
  virtual Status vote(const std::string& voter, const std::string& post, bool up) = 0;
  virtual Status unvote(const std::string& voter, const std::string& post) = 0;
  virtual Status accept(const std::string& user, const std::string& answer) = 0;
  virtual int reputation(const std::string& user) const = 0;
  virtual int score(const std::string& post) const = 0;
  virtual std::vector<AnswerInfo> answers(const std::string& question) const = 0;
};

std::unique_ptr<Site> makeSite();

}  // namespace qa

namespace qa {

// makeCappedSite(dailyCap) is a site with everything makeSite() has, plus days and a cap (dailyCap >= 1, otherwise nullptr).
// Every vote belongs to the DAY it was cast (the replaced vote's day does not carry over). setDay(day) moves the clock:
// InvalidInput when day is below the current day (never backwards) or above kMaxDay; the same day is fine; the clock
// starts at day 0.
//
// THE CAP: for each user and each day, the points earned from UPVOTES that were cast that day count at most dailyCap
// in total. Everything else is uncapped: downvote penalties (to the author and to the voter), and the acceptance points
// (+15 and +2). So a user's reputation is 1 + sum over days of (min(dailyCap, upvote points of that day) + penalties of
// that day) + acceptance points, never below 1. Because reputation is derived, taking a vote back or removing a post
// can lift a day back under the cap, and the numbers must come out as if the vote had never been cast.
class CappedSite : public Site {
 public:
  virtual Status setDay(int day) = 0;
};

std::unique_ptr<CappedSite> makeCappedSite(int dailyCap);

}  // namespace qa

namespace {
struct Model {
  struct Post {
    bool question;
    std::string author, parent;
    int seq;
  };
  std::vector<std::string> users;
  std::map<std::string, Post> posts;
  std::map<std::pair<std::string, std::string>, bool> votes;  // (post, voter) -> up
  std::map<std::string, std::string> accepted;                // question -> answer
  int seq = 0;

  bool hasUser(const std::string& u) const { return std::find(users.begin(), users.end(), u) != users.end(); }

  int reputation(const std::string& user) const {
    if (!hasUser(user)) return 0;
    int total = 1;
    for (const auto& v : votes) {
      const Post& p = posts.at(v.first.first);
      if (v.second) {
        if (p.author == user) total += p.question ? 5 : 10;
      } else {
        if (p.author == user) total -= 2;
        if (!p.question && v.first.second == user) total -= 1;
      }
    }
    for (const auto& a : accepted) {
      const std::string& asker = posts.at(a.first).author;
      const std::string& writer = posts.at(a.second).author;
      if (asker == writer) continue;
      if (writer == user) total += 15;
      if (asker == user) total += 2;
    }
    return total < 1 ? 1 : total;
  }
  int score(const std::string& post) const {
    int total = 0;
    for (const auto& v : votes) {
      if (v.first.first == post) total += v.second ? 1 : -1;
    }
    return total;
  }
  std::string order(const std::string& q) const {
    auto it = posts.find(q);
    if (it == posts.end() || !it->second.question) return "";
    std::vector<std::string> ids;
    for (const auto& p : posts) {
      if (!p.second.question && p.second.parent == q) ids.push_back(p.first);
    }
    const std::string acc = accepted.count(q) ? accepted.at(q) : "";
    std::sort(ids.begin(), ids.end(), [&](const std::string& a, const std::string& b) {
      if ((a == acc) != (b == acc)) return a == acc;
      if (score(a) != score(b)) return score(a) > score(b);
      return posts.at(a).seq < posts.at(b).seq;
    });
    std::string out;
    for (const auto& id : ids) out += (out.empty() ? "" : " ") + id + (id == acc ? "*" : "") + ":" + std::to_string(score(id));
    return out;
  }
  Status ask(const std::string& id, const std::string& a) {
    if (id.empty() || id.size() > 32) return Status::InvalidInput;
    if (!hasUser(a)) return Status::UnknownUser;
    if (posts.count(id)) return Status::DuplicatePost;
    posts[id] = {true, a, "", seq++};
    return Status::Ok;
  }
  Status answer(const std::string& id, const std::string& q, const std::string& a) {
    if (id.empty() || id.size() > 32) return Status::InvalidInput;
    if (!hasUser(a)) return Status::UnknownUser;
    if (!posts.count(q) || !posts.at(q).question) return Status::UnknownPost;
    if (posts.count(id)) return Status::DuplicatePost;
    posts[id] = {false, a, q, seq++};
    return Status::Ok;
  }
  Status vote(const std::string& v, const std::string& p, bool up) {
    if (!hasUser(v)) return Status::UnknownUser;
    if (!posts.count(p)) return Status::UnknownPost;
    if (posts.at(p).author == v) return Status::SelfVote;
    if (!up && reputation(v) < 15) return Status::LowReputation;
    auto it = votes.find({p, v});
    if (it != votes.end() && it->second == up) return Status::AlreadyVoted;
    votes[{p, v}] = up;
    return Status::Ok;
  }
  Status unvote(const std::string& v, const std::string& p) {
    if (!hasUser(v)) return Status::UnknownUser;
    if (!posts.count(p)) return Status::UnknownPost;
    if (!votes.count({p, v})) return Status::NoVote;
    votes.erase({p, v});
    return Status::Ok;
  }
  Status accept(const std::string& u, const std::string& a) {
    if (!hasUser(u)) return Status::UnknownUser;
    if (!posts.count(a)) return Status::UnknownPost;
    if (posts.at(a).question) return Status::WrongKind;
    const std::string q = posts.at(a).parent;
    if (posts.at(q).author != u) return Status::NotAuthor;
    if (accepted.count(q) && accepted.at(q) == a) return Status::AlreadyAccepted;
    accepted[q] = a;
    return Status::Ok;
  }
};

class SiteImpl : public qa::ModeratedSite {
 public:
  explicit SiteImpl(std::unique_ptr<ReputationPolicy> policy)
      : policy_(std::move(policy)), ledger_(posts_, votes_, accepts_), lister_(posts_, votes_, accepts_), remover_(posts_, votes_, accepts_) {}

  qa::Status addUser(const std::string& name) override {
    if (!isValidName(name)) return qa::Status::InvalidInput;
    if (users_.contains(name)) return qa::Status::DuplicateUser;
    users_.add(name);
    return qa::Status::Ok;
  }

  qa::Status ask(const std::string& id, const std::string& author) override {
    if (!isValidName(id)) return qa::Status::InvalidInput;
    if (!users_.contains(author)) return qa::Status::UnknownUser;
    if (posts_.contains(id)) return qa::Status::DuplicatePost;
    posts_.addQuestion(id, author);
    return qa::Status::Ok;
  }

  qa::Status answer(const std::string& id, const std::string& question, const std::string& author) override {
    if (!isValidName(id)) return qa::Status::InvalidInput;
    if (!users_.contains(author)) return qa::Status::UnknownUser;
    const Post* asked = posts_.find(question);
    if (asked == nullptr || asked->kind != PostKind::Question) return qa::Status::UnknownPost;
    if (posts_.contains(id)) return qa::Status::DuplicatePost;
    posts_.addAnswer(id, question, author);
    return qa::Status::Ok;
  }

  qa::Status vote(const std::string& voter, const std::string& post, bool up) override {
    if (!users_.contains(voter)) return qa::Status::UnknownUser;
    const Post* target = posts_.find(post);
    if (target == nullptr) return qa::Status::UnknownPost;
    if (target->author == voter) return qa::Status::SelfVote;
    if (!up && reputation(voter) < qa::kMinDownvoteReputation) return qa::Status::LowReputation;
    const Vote* existing = votes_.find(post, voter);
    if (existing != nullptr && existing->up == up) return qa::Status::AlreadyVoted;
    votes_.put({voter, post, up, clock_.today()});
    return qa::Status::Ok;
  }

  qa::Status unvote(const std::string& voter, const std::string& post) override {
    if (!users_.contains(voter)) return qa::Status::UnknownUser;
    if (!posts_.contains(post)) return qa::Status::UnknownPost;
    if (votes_.find(post, voter) == nullptr) return qa::Status::NoVote;
    votes_.erase(post, voter);
    return qa::Status::Ok;
  }

  qa::Status accept(const std::string& user, const std::string& answer) override {
    if (!users_.contains(user)) return qa::Status::UnknownUser;
    const Post* chosen = posts_.find(answer);
    if (chosen == nullptr) return qa::Status::UnknownPost;
    if (chosen->kind != PostKind::Answer) return qa::Status::WrongKind;
    if (posts_.find(chosen->parent)->author != user) return qa::Status::NotAuthor;
    if (accepts_.acceptedFor(chosen->parent) == answer) return qa::Status::AlreadyAccepted;
    accepts_.accept(chosen->parent, answer);
    return qa::Status::Ok;
  }

  int reputation(const std::string& user) const override {
    if (!users_.contains(user)) return 0;
    return rewards::reputationFrom(policy_->pointsFrom(ledger_.eventsOf(user)));
  }

  int score(const std::string& post) const override { return votes_.score(post); }

  std::vector<qa::AnswerInfo> answers(const std::string& question) const override { return lister_.listFor(question); }

  qa::Status setDay(int day) override { return clock_.moveTo(day) ? qa::Status::Ok : qa::Status::InvalidInput; }

  qa::Status remove(const std::string& user, const std::string& post) override {
    if (!users_.contains(user)) return qa::Status::UnknownUser;
    const Post* target = posts_.find(post);
    if (target == nullptr) return qa::Status::UnknownPost;
    if (target->author != user) return qa::Status::NotAuthor;
    remover_.remove(*target);
    return qa::Status::Ok;
  }

 private:
  UserDirectory users_;
  PostBoard posts_;
  VoteBook votes_;
  AcceptBook accepts_;
  DayClock clock_;
  std::unique_ptr<ReputationPolicy> policy_;
  Ledger ledger_;
  AnswerLister lister_;
  PostRemover remover_;
};

// Every vote that currently stands: at most one per voter per post.
class VoteBook {
 public:
  const Vote* find(const std::string& post, const std::string& voter) const {
    const auto byPost = votes_.find(post);
    if (byPost == votes_.end()) return nullptr;
    const auto it = byPost->second.find(voter);
    return it == byPost->second.end() ? nullptr : &it->second;
  }

  void put(const Vote& vote) { votes_[vote.post][vote.voter] = vote; }

  void erase(const std::string& post, const std::string& voter) {
    const auto byPost = votes_.find(post);
    if (byPost != votes_.end()) byPost->second.erase(voter);
  }

  void eraseAllOn(const std::string& post) { votes_.erase(post); }

  int score(const std::string& post) const {
    const auto byPost = votes_.find(post);
    if (byPost == votes_.end()) return 0;
    int total = 0;
    for (const auto& entry : byPost->second) total += entry.second.up ? 1 : -1;
    return total;
  }

  void forEach(const std::function<void(const Vote&)>& visit) const {
    for (const auto& byPost : votes_) {
      for (const auto& entry : byPost.second) visit(entry.second);
    }
  }

 private:
  std::map<std::string, std::map<std::string, Vote>> votes_;
};
