1b:T5ce,# Chess: piece movement, check detection and checkmate

You are building the rules engine of a chess game: no screen, no AI, just the part that says whether a move is allowed and what the position is afterwards. Two players share one `Game` object. A caller names two squares ("e2", "e4"); the engine moves the piece or says why not. It must also answer "where can this piece go?", "is the side to move in check?" and "is the game over?".

What you know so far:

- Six kinds of piece, each with its own way of moving: pawns, knights, bishops, rooks, queens and kings.
- A piece may not land on a friend, sliders may not jump over pieces, and a pawn is special (it moves one way and captures another, and it becomes something else on the last rank).
- A move that leaves your own king attacked is not allowed, whatever the piece.
- The game ends when the side to move has no legal move.
- White moves first, and the sides alternate.

Your task: design and implement it behind the `chess::Game` interface in `api.h` (`makeGame()` and `makeGameFrom()` are yours to define). The hidden tests call only that interface. Ask the interviewer questions first: "what is a legal move, exactly?", "what does move() answer, and in which order does it check?", "what ends the game, and is a draw different from a loss?" and "which of the special rules are in?" are where first drafts go wrong. 1c:T28d5,# Editorial: Chess with check detection, castling, en passant and undo

## Requirements
Functional: a `Game` for two players with `move(from, to, promoteTo)`, `pieceAt`, `turn`, `inCheck`, `outcome` and `legalMoves(square)`, a standard start (`makeGame`) and a position built from text (`makeGameFrom`). Then castling and en passant, and then `undo`.

Hidden in the brief and revealed by good questions: the notation of squares and what is `InvalidSquare`; the movement of every piece, the pawn's push versus capture and its start rank per colour; that a promotion is chosen by the caller (default queen, `InvalidPromotion` for a pawn or king, ignored on other moves); that legality means "my king is not attacked after the move", which covers pins, check evasions, double check and a king stepping back along a rook's line; the check order of `move` (GameOver, InvalidSquare, Empty, NotYourTurn, IllegalMove, InvalidPromotion) and that a refused move changes nothing; that checkmate and stalemate differ (no legal move with and without check) and that `GameOver` is checked first; that `legalMoves` is sorted and lists a promotion square once; that the basic game has no castling and no en passant; and which positions `makeGameFrom` refuses.

**Change Storm 1, castling and en passant:** the king and a never-moved rook may swap sides under conditions (empty between, not in check, not through or into an attacked square), the rights are lost on a king move, a rook move and a rook capture on its corner, and a position from text infers the rights from the home squares. A pawn that advanced two squares can be captured on the very next move by an adjacent enemy pawn as if it had advanced one, and that capture must also pass the king-safety test.

**Change Storm 2, undo:** `undo()` takes back the last accepted move, restoring everything (turn, captured piece, promotion, rook, rights, en passant chance, outcome), works after checkmate, and has the starting position as its floor. `moveCount()` is the depth of the history.

## Reference design
`Square` and `Board` are small value types: the board is 64 cells, copying it is how a trial move is tried, and a `Position` adds the turn, the castling rights and the en passant square, so one `Position` is the entire state of a game. `PieceRules` is the Strategy for how one kind of piece behaves, with two questions: `attacks` (the squares it attacks, including the first piece on a line, whatever its colour) and `moves` (its own moves). `ReachRule` is the shared case where moves are the attacked squares minus those held by a friend; `StepRule` (knight, king) and `SlideRule` (bishop, rook, queen) are data-driven by their offsets, and `PawnRule` implements both questions on its own because a pawn pushes where it does not attack. A `RuleTable` finds the rule by kind, so there is no switch on the piece kind anywhere. `CheckDetector` answers "is this square attacked by that side?" by asking each enemy piece what it attacks, and "is this king in check?" with it.

`MoveGenerator::legalFrom` takes the piece's moves plus any special moves, applies each to a copy with `MoveApplier` (the only place a move changes a position) and keeps those after which the mover's king is not attacked. `GameQueries` owns the state and every read-only question (`pieceAt`, `turn`, `inCheck`, `outcome`, `legalMoves`) and computes the outcome after each change; `GameImpl` holds the commands, `move` (validate in the documented order, look the move up among the legal moves of the piece, push the old position on the history, apply) and `undo`. `PositionParser` turns text rows into a position and refuses impossible ones.

Storm 1 added no branch to the piece rules or to the legality test. `SpecialMove` is an extension interface with two methods, `generate` (extra moves for a piece) and `afterMove` (finish a move and update the state it keeps). `CastlingRule` adds the king's two-square move when the conditions hold, moves the rook, and updates the rights by one rule: a move that touches a king's or rook's home square (from it or onto it) removes the matching rights. `EnPassantRule` adds the diagonal capture when the position has an en passant square, removes the passed pawn, and clears and sets the en passant square after every move. A `RuleBook` is the piece table plus the list of specials: the basic game has an empty list, the full game has two. Storm 2 was `history_`, a stack of whole positions, which is why `undo` knows no rules.

## Alternatives
- **One class per piece with a virtual `moves`.** A `Piece` hierarchy (`Knight : Piece`) is what most interviews draw. It reads well and puts the rule next to the data, but the piece must then be cloneable (to copy a board for trial moves) or the board must hold pointers into shared objects. Here a piece is a value (colour and kind) and the behaviour is a stateless strategy found by kind: copying a position is trivial and a rule object is created once.
- **Make and unmake in place instead of copying.** Faster and the standard in engines, and a source of bugs (every rule must undo itself, including en passant and castling rights). A copy is obviously correct, and the position is 70 bytes of cells.
- **Derive attacks from moves.** Tempting for everyone except the pawn, whose pushes are not attacks and whose attacks are not moves, so two methods are cleaner than a flag.
- **Pseudo-legal generation, then discover illegality when the king would be captured.** Engines do this and defer the king-safety test to the search; for a rules API the answer to "may I?" must be exact now, so the test is applied at generation time.
- **A flag for "castled" or "has moved" on each piece.** Works for castling but puts game history on the piece and makes copies and undo carry flags around; rights as position state, updated by one rule, are easier to restore and to test.
- **Commands with their own undo.** A `MoveCommand` that records what it changed (Command pattern). Memory-light and fast; every special rule must also implement the reversal. A snapshot per ply is simpler and cannot forget a field; the editorial recommends it until a profile says otherwise.
- **Bitboards.** A different representation for speed (see 10x), not a different design.

## Trade-offs
- **Copy the position to test legality.** One test for every case and no special code for pins, checks or en passant, at the price of a copy per candidate move. Worth it far beyond the size of this problem; an engine would pay for a faster scheme.
- **Rules as data (offset lists, a table by kind).** Adding or changing a piece is one entry; the cost is one virtual call per question and the discipline of keeping rules stateless.
- **Castling rights in the position.** The rights are history, not geometry, so they live in state and are updated by one rule that watches four squares. The price is that a position from text needs a convention (rights inferred from the home squares), which is documented in the interface.
- **Special moves as an extension interface.** Open to new rules (a variant could add one), at the price of every special being called after every move (a cheap call each) and a move type that says what it is.
- **Snapshot history.** Undo cannot go wrong and knows no rules; memory is proportional to the number of plies. For a human game, trivial.
- **Recomputing the outcome after each change.** It finds "any legal move" by generating moves until the first one, so each change costs about one legality pass; caching it in the state avoids asking twice.
- **Strict interface.** Statuses with an order, refused calls changing nothing, a sorted list: callers and tests can rely on all of it.

## What breaks at 10x
- **Search**: a chess engine needs millions of positions per second. Bitboards, magic lookups for sliders, in-place make/unmake, pin and check masks instead of trying every move, and incremental hashing. The classes keep their jobs, the representation changes.
- **Memory**: a long game stores one position per ply; a server hosting millions of games should store the move list and rebuild or snapshot every N plies.
- **Many games**: one game per object, one lock per game, games sharded by id; the rules engine is pure, so it can run in the client for instant feedback and on the server as the truth.
- **More rules**: draws by repetition (needs a position hash that includes rights and the en passant square), the fifty-move counter, insufficient material, and clocks. All are state next to the position and one more query on the game; none changes the piece rules.
- **Variants**: Chess960 breaks the home-square assumptions for castling (rights and rook files become data), fairy pieces are new `PieceRules`, and a different board size breaks the `8` in `Square`. The first and the last are the ones that show where the hard-coded numbers are.
- **Notation**: SAN, UCI and FEN are adapters on top of the interface; parsing "Nbd2" needs `legalMoves` to disambiguate, which is a good reason it is public.

## Level signals
- **SDE II:** the base problem correct: each piece moving as the rules say (including the pawn's different push, capture and start rank), legality as "the king is not attacked after the move", check, checkmate and stalemate, promotion, the documented check order, and `makeGameFrom` refusing impossible positions. Writes the piece behaviour as polymorphism or a table instead of a switch and names the boundary cases (blocked pawn, pinned piece, stalemate) before being asked.
- **Senior:** all of the above plus attack detection that is separate from move generation, the legality test on a copy so that no special case exists for pins or evasions, castling and en passant as an extension that did not touch the piece rules, the castling rights as state with the capture-on-the-corner case, the en passant legality case (the exposed rank), and undo as a whole-state restore. Brings up perft as the way to test a generator.
- **Staff:** treats the engine as a core with a clear representation boundary (bitboards, in-place make and unmake, pin masks) and the service around it: authoritative server-side validation, an append-only move log per game with snapshots, sharding by game id with one writer per game, clocks on the server, and the same rules code in the client. Discusses repetition and the fifty-move rule as position state with hashing, and variants (Chess960) as what breaks hard-coded assumptions.

#include <memory>
#include <string>
#include <vector>

namespace chess {

enum class Color { White, Black };
enum class Kind { Pawn, Knight, Bishop, Rook, Queen, King };

struct Piece {
  Color color;
  Kind kind;
};

enum class Status {
  Ok,
  InvalidSquare,     // a square is not written as a lower-case file a..h followed by a rank 1..8
  Empty,             // there is no piece on the square (for move() and pieceAt())
  NotYourTurn,       // the piece on the square belongs to the side that is not to move
  IllegalMove,       // the piece cannot move there, or the move leaves the mover's own king attacked
  InvalidPromotion,  // a pawn reaches the last rank and the requested piece is a pawn or a king
  GameOver,          // the side to move is checkmated or stalemated
  NothingToUndo,     // reserved for a later interface; nothing here returns it
};

enum class Outcome {
  Ongoing,
  Checkmate,  // the side to move is in check and has no legal move: the other side has won
  Stalemate,  // the side to move is NOT in check and has no legal move: a draw
};

// A game of chess between two players who share one object. Squares are written "e4": a lower-case file and a rank.
//
// MOVEMENT. Every piece moves as in the standard game, with these simplifications for this exercise:
//   Pawn    one square forward onto an empty square; two squares forward from its start rank (rank 2 for White,
//           rank 7 for Black) when both squares in front of it are empty; one square diagonally forward onto a square
//           that holds an enemy piece. White moves up the ranks, Black down. A pawn that reaches the last rank is
//           promoted to the piece named by promoteTo (Queen, Rook, Bishop or Knight).
//   Knight  the eight L-shaped jumps; it may jump over pieces.
//   Bishop, Rook, Queen   any distance along its lines until the first piece: an enemy piece there may be captured,
//           a friendly piece blocks and cannot be captured.
//   King    one square in any direction.
// No piece captures a piece of its own colour. This basic game has NO castling and NO en passant: a king that tries to
// move two squares, or a pawn that tries to capture a square that is empty, is an IllegalMove.
//
// CHECK. A king is in check when an enemy piece attacks its square (a pawn attacks the two squares diagonally in front
// of it, not the square it pushes to). A move is legal only if the mover's own king is not attacked afterwards: so a pinned
// piece may move only along the line of the pin, a king may not step onto an attacked square, and while in check the
// move must capture the checker, block it, or move the king.
//
// move(from, to, promoteTo) CHECK ORDER: GameOver, InvalidSquare (either square), Empty, NotYourTurn, IllegalMove,
// InvalidPromotion. promoteTo is ignored unless the move is a promotion (a pawn reaching the last rank); for a promotion it
// must be Queen, Rook, Bishop or Knight, or the call is InvalidPromotion. A refused call changes nothing.
class Game {
 public:
  virtual ~Game() = default;

  virtual Status move(const std::string& from, const std::string& to, Kind promoteTo = Kind::Queen) = 0;

  // Ok and the piece, Empty for an empty square (out untouched), InvalidSquare for a bad name.
  virtual Status pieceAt(const std::string& square, Piece& out) const = 0;

  virtual Color turn() const = 0;      // the side to move
  virtual bool inCheck() const = 0;    // is the side to move in check?
  virtual Outcome outcome() const = 0;

  // The squares the piece on `from` may legally move to, sorted by name ("a3" < "a4" < "b1"), each once (a promotion
  // square appears once). Empty for an invalid square, an empty square or a piece of the side that is not to move.
  virtual std::vector<std::string> legalMoves(const std::string& from) const = 0;
};

// The standard starting position, White to move.
std::unique_ptr<Game> makeGame();

// A game from a position. `rows` has 8 strings of 8 characters, rank 8 first, file a first: 'K','Q','R','B','N','P' are
// White pieces, 'k','q','r','b','n','p' are Black pieces and '.' is an empty square. `toMove` is the side to move.
// Returns nullptr for a position that cannot exist: wrong shape or characters, not exactly one king of each colour, a pawn
// on rank 1 or 8, or the side that is NOT to move already in check. The outcome of a position that is already checkmate
// or stalemate is reported at once.
std::unique_ptr<Game> makeGameFrom(const std::vector<std::string>& rows, Color toMove);

}  // namespace chess

std::vector<std::string> rowsOf(const std::string& placement) {
  std::vector<std::string> rows(1);
  for (char c : placement) {
    if (c == '/') rows.emplace_back();
    else if (c >= '1' && c <= '8') rows.back() += std::string(static_cast<std::size_t>(c - '0'), '.');
    else rows.back() += c;
  }
  return rows;
}

}

std::string join(const std::vector<std::string>& names) {
  std::string out;
  for (const auto& n : names) out += (out.empty() ? "" : " ") + n;
  return out;

// "e2e4" or "e7e8n": plays one move, the optional fifth letter names the promotion piece.
Status play(chess::Game& g, const std::string& text) {
  Kind promote = Kind::Queen;
  if (text.size() == 5) promote = text[4] == 'n' ? Kind::Knight : text[4] == 'b' ? Kind::Bishop : text[4] == 'r' ? Kind::Rook : Kind::Queen;
  return g.move(text.substr(0, 2), text.substr(2, 2), promote);
}

bool playAll(chess::Game& g, const std::string& line) {
  std::size_t start = 0;
  while (start < line.size()) {
    std::size_t end = line.find(' ', start);
    if (end == std::string::npos) end = line.size();
    if (play(g, line.substr(start, end - start)) != Status::Ok) return false;
    start = end + 1;
  }
  return true;
}

  if (g.pieceAt(square, p) != Status::Ok) return '.';
  static const std::string kinds = "PNBRQK";
  const char c = kinds[static_cast<std::size_t>(p.kind)];
  return p.color == Color::White ? c : static_cast<char>(c - 'A' + 'a');
}

std::string placementOf(const chess::Game& g) {
  std::string out;
  for (int rank = 8; rank >= 1; --rank) {
    for (char file = 'a'; file <= 'h'; ++file) out += letter(g, std::string{file, static_cast<char>('0' + rank)});
    if (rank > 1) out += '/';
  }
  return out;
}

// The number of moves of the side to move, a promotion counted as the four moves it is.
long long countMoves(const chess::Game& g) {
  long long total = 0;
  for (char file = 'a'; file <= 'h'; ++file) {
    for (char rank = '1'; rank <= '8'; ++rank) {
      const std::string from{file, rank};
      const char c = letter(g, from);
      const bool pawn = c == 'P' || c == 'p';
      for (const auto& to : g.legalMoves(from)) total += (pawn && (to[1] == '8' || to[1] == '1')) ? 4 : 1;
    }
  }
  return total;
}

// Counts the positions `depth` moves ahead. The basic game has no hidden state, so a position is rebuilt from what
// the board shows.
long long perft(const chess::Game& g, int depth) {
  if (depth == 1) return countMoves(g);
  long long total = 0;
  const std::string placement = placementOf(g);
  for (char file = 'a'; file <= 'h'; ++file) {
    for (char rank = '1'; rank <= '8'; ++rank) {
      const std::string from{file, rank};
      const char c = letter(g, from);
      for (const auto& to : g.legalMoves(from)) {
        const bool promotion = (c == 'P' || c == 'p') && (to[1] == '8' || to[1] == '1');
        for (Kind k : {Kind::Queen, Kind::Rook, Kind::Bishop, Kind::Knight}) {
          auto next = position(placement, g.turn());
          if (!next || next->move(from, to, k) != Status::Ok) return -1000000;
          total += perft(*next, depth - 1);
          if (!promotion) break;
        }
      }
    }
  }
  return total;
}

// "e2e4" or "e7e8n": plays one move, the optional fifth letter names the promotion piece.
Status play(chess::Game& g, const std::string& text) {
  Kind promote = Kind::Queen;
  if (text.size() == 5) promote = text[4] == 'n' ? Kind::Knight : text[4] == 'b' ? Kind::Bishop : text[4] == 'r' ? Kind::Rook : Kind::Queen;
  return g.move(text.substr(0, 2), text.substr(2, 2), promote);

bool playAll(chess::Game& g, const std::string& line) {
  std::size_t start = 0;
  while (start < line.size()) {
    std::size_t end = line.find(' ', start);
    if (end == std::string::npos) end = line.size();
    if (play(g, line.substr(start, end - start)) != Status::Ok) return false;
    start = end + 1;
  }
  return true;
}

// The number of moves of the side to move, a promotion counted as the four moves it is.
long long countMoves(const chess::Game& g) {
  long long total = 0;
  for (char file = 'a'; file <= 'h'; ++file) {
    for (char rank = '1'; rank <= '8'; ++rank) {
      const std::string from{file, rank};
      const char c = letter(g, from);
      const bool pawn = c == 'P' || c == 'p';
      for (const auto& to : g.legalMoves(from)) total += (pawn && (to[1] == '8' || to[1] == '1')) ? 4 : 1;
    }
  }
  return total;
}


struct Step {
  std::string from;
  std::string to;
  Kind promote;

// A full game has hidden state (castling rights, the en passant chance), so a position is rebuilt by replaying its moves.
std::unique_ptr<chess::Game> replay(const std::string& placement, Color toMove, const std::vector<Step>& path) {
  auto g = position(placement, toMove);
  for (const Step& s : path) {
    if (!g || g->move(s.from, s.to, s.promote) != Status::Ok) return nullptr;
  }
  return g;
}

// "e2e4" or "e7e8n": plays one move, the optional fifth letter names the promotion piece.
Status play(chess::Game& g, const std::string& text) {
  Kind promote = Kind::Queen;
  if (text.size() == 5) promote = text[4] == 'n' ? Kind::Knight : text[4] == 'b' ? Kind::Bishop : text[4] == 'r' ? Kind::Rook : Kind::Queen;
  return g.move(text.substr(0, 2), text.substr(2, 2), promote);

bool playAll(chess::Game& g, const std::string& line) {

  while (start < line.size()) {

    if (end == std::string::npos) end = line.size();
    if (play(g, line.substr(start, end - start)) != Status::Ok) return false;
    start = end + 1;
  }
  return true;
}

// The number of moves of the side to move, a promotion counted as the four moves it is.
long long countMoves(const chess::Game& g) {
  long long total = 0;
  for (char file = 'a'; file <= 'h'; ++file) {
    for (char rank = '1'; rank <= '8'; ++rank) {
      const std::string from{file, rank};
      const char c = letter(g, from);
      const bool pawn = c == 'P' || c == 'p';
      for (const auto& to : g.legalMoves(from)) total += (pawn && (to[1] == '8' || to[1] == '1')) ? 4 : 1;
    }
  }
  return total;
}


// Everything an observer can see: if two games have the same signature they behave the same from here on.
std::string signature(const chess::Game& g) {
  std::string out = placementOf(g) + (g.turn() == Color::White ? " w " : " b ");
  out += std::to_string(static_cast<int>(g.outcome())) + (g.inCheck() ? "+" : "-");
  for (char file = 'a'; file <= 'h'; ++file) {
    for (char rank = '1'; rank <= '8'; ++rank) {
      const std::string from{file, rank};
      const std::string moves = movesOf(g, from);
      if (!moves.empty()) out += " " + from + ":" + moves;
    }
  }
  return out;
}

bool walkAndUndo(const std::string& placement, Color toMove, std::uint64_t seed, int plies) {

      }
