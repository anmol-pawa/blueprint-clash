1b:T4b4,# In-memory file system

You are building the storage core of a small operating-system simulator: a tree of directories and files held entirely in memory. Programs create directories, write and read files, list a directory, delete things and move them around, and they give you paths as strings. They are not careful with those strings, and they are not forgiving when a "simple" call corrupts the tree.

What you know so far:

- There is one root directory, "/". Everything lives below it.
- A directory holds named entries; each entry is a file with content or another directory.
- Callers refer to entries by absolute path: "/home/ada/notes.txt".
- Calls report what went wrong instead of crashing: a missing parent, a name that is already taken, a file where a directory was expected.

Your task: design and implement it behind the `fs::FileSystem` interface in `api.h`. The hidden tests call only that interface. Ask the interviewer questions first: the brief is deliberately incomplete, and "what exactly is a path, and which error wins when several apply?" is where first drafts go wrong. Expect a request to search by name pattern, and then a request for symbolic links, after you have finished.
1c:T1ef9,# Editorial: In-memory file system

## Requirements
Functional: one tree under the root "/"; mkdir, write, read, remove, list, size, kind and move on absolute paths; every call reports a status instead of crashing; searching by name pattern; symbolic links.

Hidden in the brief and revealed by good questions: paths are textual (`.`, `..`, repeated and trailing slashes, a 32-character name limit that applies even to parts `..` removes, and `..` at the root staying at the root); invalid paths are reported before any lookup; a lookup goes from the root down, so a missing directory is NotFound and a file on the way is NotADirectory; mkdir needs its parent; write replaces the whole content; remove takes a file or an empty directory; list replaces the caller's vector with sorted direct children; the size of a directory is everything below it; move never overwrites, carries a whole subtree, refuses to move into itself and has a written check order; failed calls change nothing and leave outputs alone.

**Change Storm 1, search:** `find(dir, pattern)` matches names (not paths) with `*` and `?`, over every level, directories included, results depth-first with a directory before its content.

**Change Storm 2, symbolic links:** a link is an entry that holds a path. Links in the middle of a path are always followed; a final link is followed by read, write, list, size and find and not by kind, readLink, remove, move, mkdir and symlink. Writing through a dangling link creates its target, `..` is applied to the text before links, eight hops are allowed and the ninth is LinkLoop, directory sizes skip links, find does not descend through them, and a move into itself through a link is refused.

## Reference design
- `FileSystemImpl` is the facade. Each call is a few lines: ask the resolver where the path leads, check the kind, change the tree, return a status. It parses no strings itself.
- `Path` is a value: the normalised names from the root. It is the only code that knows about slashes, dots and the name limit, so every other class works with names.
- `Node` is the Composite: `File`, `Directory` and `Link` answer `kind()` and `bytes()`, and a directory's `bytes()` is the sum of its children's. Safe downcast methods (`asDirectory`, `asFile`, `asLink`) replace `dynamic_cast` and type tags.
- `Resolver` is the one place that walks a path. It returns a `Located` result: the directory that holds the entry, the name, and the entry (null when it is not there yet), or a status. A `Follow` flag says whether a link in the last part is followed. Everything that makes a failed lookup NotFound or NotADirectory lives here.
- `Glob` matches one name against a pattern in linear time (remember the last star, retry with one more character swallowed). `Finder` walks the tree depth-first over sorted children and collects matches.
- `Link` is a node that holds a `Path`. It counts as 0 bytes. The resolver replaces a followed link by its target and counts hops.

**Storm 1 in the reference:** `Glob`, `Finder` and one method on the facade. No node class changes: the walker uses the directory's children and the safe downcast.

**Storm 2 in the reference:** `Link` (a new node), a branch and a counter in `Resolver::locate`, two facade methods (`symlink`, `readLink`), and `Directory::holds` for the move check. File and Directory are untouched because lookups already went through one class. The other calls pick `Follow::Last` or `Follow::NotLast` and nothing more.

## Alternatives
- **Visitor over the node family.** `accept(Visitor&)` on every node and one visitor per walk (size, find, du). Clean when walks multiply and node kinds are stable, and each new node kind means touching every visitor. Safe downcasts in a walker are lighter for two walks; at five or six, a Visitor wins.
- **Virtual `find` and `size` on `Node`.** Each node recurses itself. Natural for `size` (the reference does it), and a poor fit for every new traversal because File, Directory and Link all change.
- **A flat map from path string to entry.** Trivial lookup (this is also the test's model) and wrong for `list`, `move` of a directory (every key below it is rewritten) and `size` (a scan). Fine for a key-value store, not for a tree.
- **Parent pointers in every node.** Makes `..` physical and the `holds` check trivial, at the cost of keeping two links in sync on every move. The reference keeps ownership one-directional (unique_ptr down) and walks from the root.
- **One lookup written into each call.** Eleven copies of the path walk; when links arrive each must learn the link rule and the hop count, and they will not agree. A single `Resolver` is the whole change.
- **Lazy path strings: store each node's full path.** Every move rewrites a subtree's paths. Avoid.
- **A cached size on every directory.** O(1) `size`, but every write, remove and move must update all ancestors, and links make the cache wrong. Recompute until measurements say otherwise.

## Trade-offs
Reporting a status for every case, rather than throwing, makes callers deal with failure at each call, and it makes the interface testable down to the order of checks. The cost is a long contract: which error wins when several apply is part of the interface and is written down.

Applying `..` to the text is simple, needs no parent pointers and is easy to test. A real kernel applies `..` to the directory it has actually reached, which differs after a link; the simplification is deliberate and stated, and the follow-up on it is a standard senior question.

Following links in the resolver makes every operation correct by construction, and it puts a rule (hops, last-part following) in a place that every call depends on. The alternative, a flag per call, is what the code does: the call states whether the last part is followed and the resolver does the rest.

`map<string, unique_ptr<Node>>` gives sorted `list` and `find` for free and costs O(log n) per lookup and a node-per-entry memory layout. A `vector` of sorted pairs is smaller and slower to insert; a hash map is faster and then sorts on `list`.

## What breaks at 10x
A directory with a million entries makes `list` copy a million names and `find` walk everything. Page `list` with a cursor, index names (a trie or a sorted structure) and give `find` a way to stop early; memory per entry (a map node, a node object, a string) becomes the cost to measure. Deep trees make the recursive `bytes()` and `find` a stack hazard at depth in the tens of thousands: iterate with an explicit stack. Concurrent callers need a lock: one reader-writer lock first, then a lock per directory taken hand over hand, where `move` needs a global lock order and a descendant check under the lock, otherwise two moves can make a cycle. Large files want chunked storage and copy-on-write snapshots; links across mounts and relative links add path rules the hop counter does not cover. Crash safety needs a journal of the mutations, which is a Command log like the text editor's history.

## Level signals
- **SDE2:** a directory tree that works for the common calls; normalises paths, returns the right error for a missing parent and a taken name, sorts `list`, refuses a non-empty `remove`, never overwrites in `move`.
- **Senior:** separates path text from the tree (a `Path`), uses a Composite so `size` is a recursion over objects, centralises the walk in one resolver, states and tests the order of checks, refuses a move into itself, adds the search as a walker without editing the nodes, and adds links as a new node plus one rule in the resolver; compares with a flat-map model in a randomised test.
- **Staff:** talks about physical versus textual `..`, hop limits and loop detection, locking order for moves, cached sizes and when they pay, journals and snapshots, per-mount trees, and what to measure (entries per directory, depth, memory per entry, lookup latency) before changing the layout.

// Public API for the In-memory file system problem. The hidden tests only use what is declared here.
// You implement fs::makeFileSystem() (in any of your .cpp files); everything behind it is your design.
#include <cstddef>
#include <memory>
#include <string>
#include <vector>

namespace fs {

constexpr std::size_t kMaxNameLength = 32;  // longest allowed name, in characters

enum class Status {
  Ok,
  NotFound,       // the entry, or a directory on the way to it, does not exist
  AlreadyExists,  // the name is taken (by a file, a directory, or later a link)
  NotADirectory,  // a name on the way, or the one being listed, is not a directory
  IsADirectory,   // a file operation was aimed at a directory
  InvalidPath,    // malformed path, over-long name, or an operation that makes no sense (see each call)
  NotEmpty,       // remove() of a directory that still has entries
  LinkLoop,       // returned only by file systems with links (api_storm2.h); the base file system never does
  NotALink,       // returned only by file systems with links (api_storm2.h); the base file system never does
};

enum class Kind { File, Directory, Link };  // Link appears only in file systems with links (api_storm2.h)

// One tree of directories and files, starting from the root directory "/". Paths are absolute strings.
//
// PATHS. A path must start with '/'. It is split on '/'; empty parts and "." are ignored; ".." removes the part before
// it, and at the root it does nothing ("/.." is "/"). This is purely textual. A trailing '/' is fine. Every part, even
// one that ".." later removes, must be at most kMaxNameLength characters. Anything else wrong (empty string, no leading
// '/', over-long part) is InvalidPath, and that is checked before anything is looked up.
//
// Every call that returns Status leaves its output arguments and the file system unchanged unless it returns Ok.
// Looking an entry up is checked from the root down: a missing directory on the way is NotFound, a file on the way is
// NotADirectory; the entry itself is then looked at.
class FileSystem {
 public:
  virtual ~FileSystem() = default;

  // Creates one directory; its parent must exist. Taken name (including "/") is AlreadyExists.
  virtual Status mkdir(const std::string& path) = 0;

  // Creates the file or replaces the whole content of the existing one. The parent must exist. A directory at `path`
  // (including "/") is IsADirectory.
  virtual Status write(const std::string& path, const std::string& content) = 0;

  // Copies a file's content into `out`. A directory is IsADirectory.
  virtual Status read(const std::string& path, std::string& out) const = 0;

  // Removes a file or an EMPTY directory (NotEmpty otherwise). "/" is InvalidPath.
  virtual Status remove(const std::string& path) = 0;

  // Replaces `names` with the names (not paths) of the entries directly inside a directory, sorted ascending.
  virtual Status list(const std::string& path, std::vector<std::string>& names) const = 0;

  // A file's length in bytes; a directory's is the total length of every file anywhere below it (0 when empty).
  virtual Status size(const std::string& path, std::size_t& bytes) const = 0;

  // What the entry is.
  virtual Status kind(const std::string& path, Kind& out) const = 0;

  // Moves a file or a whole directory (with everything below it) to a new path, which is also its new name.
  // Checked in this order: both paths valid; `from` is "/" or `to` lies strictly inside `from` (InvalidPath: a
  // directory cannot move into itself); `from` exists; `to`'s parent exists and is a directory; `to` is free
  // (AlreadyExists, even for "to the same path"). Nothing is overwritten.
  virtual Status move(const std::string& from, const std::string& to) = 0;
};

std::unique_ptr<FileSystem> makeFileSystem();

}  // namespace fs

#include "api.h"

namespace fs {

class SearchableFileSystem : public FileSystem {
 public:
  // Finds entries below the directory `dir` whose NAME (the last part, not the whole path) matches `pattern`.
  // The pattern is matched against the whole name, case-sensitively: '*' matches any run of characters (including
  // none), '?' matches exactly one character, every other character matches itself.
  // Every level below `dir` is searched, and directories can match as well as files; `dir` itself is never a result.
  // Results are full paths (`dir` normalised, then '/', then the names down to the match), in depth-first order: a
  // directory is listed before what is inside it, and the entries of one directory come in ascending name order.
  // An empty pattern or one containing '/' is InvalidPath (checked after `dir` is parsed). Then like any lookup.
  // `found` is replaced when the call returns Ok. A search with no match is Ok with an empty result.
  virtual Status find(const std::string& dir, const std::string& pattern, std::vector<std::string>& found) const = 0;
};

std::unique_ptr<SearchableFileSystem> makeSearchableFileSystem();

}  // namespace fs

namespace fs {

constexpr int kMaxLinkHops = 8;  // most links one path lookup may follow

// A symbolic link is an entry (Kind::Link) that holds an absolute path, its target, and stands in for it.
// The target may not exist (a "dangling" link).
class LinkingFileSystem : public SearchableFileSystem {
 public:
  // Creates a link at `linkPath` to `target`. Both are parsed first (InvalidPath); the target is stored normalised.
  // Then like mkdir: the parent of `linkPath` must exist; a taken name, even one that is itself a link, is AlreadyExists.
  virtual Status symlink(const std::string& target, const std::string& linkPath) = 0;

  // Copies the stored (normalised) target of the link at `path` into `target`. Not a link: NotALink.
  virtual Status readLink(const std::string& path, std::string& target) const = 0;
};

// FOLLOWING. A path is first normalised as in api.h (so ".." is applied to the text, before any link is looked at).
// While looking an entry up:
//  - a link met in the MIDDLE of the path (not its last part) is always followed: its target replaces the parts so
//    far, the remaining parts are appended, and the walk continues from the root;
//  - a link that is the LAST part is followed by read, write, list, size and find (the directory to search), and is
//    NOT followed by kind, readLink, remove, move (either path), mkdir and symlink: these act on the link itself.
//  - write() through a link whose target does not exist creates a file there, if the target's parent directory exists.
//    read(), list(), size() and find() through a dangling link are NotFound.
// Every link followed during one lookup counts as a hop; the (kMaxLinkHops + 1)th is LinkLoop. A chain of exactly
// kMaxLinkHops links still resolves.
// size() of a directory does not follow links inside it (a link counts as 0 bytes); find() reports links by name but
// never descends through them. move() refuses (InvalidPath) a destination that lies inside the moved directory even
// when it gets there through a link.
std::unique_ptr<LinkingFileSystem> makeLinkingFileSystem();

}  // namespace fs

// ---- A model-based test: a flat map of full paths is the reference the real tree must agree with. ----
namespace {
struct Model {
  struct Entry {
    bool dir = true;
    std::string content;
  };
  std::map<std::string, Entry> entries{{"/", Entry{}}};

  static std::string parentOf(const std::string& p) { return p.rfind('/') == 0 ? "/" : p.substr(0, p.rfind('/')); }
  static std::string nameOf(const std::string& p) { return p.substr(p.rfind('/') + 1); }
  bool hasBelow(const std::string& p) const {
    for (const auto& e : entries) if (e.first.size() > p.size() + 1 && e.first.compare(0, p.size() + 1, p + "/") == 0) return true;
    return false;
  }
  // Status of looking the ancestors of p up from the root down; Ok when p's parent is a directory.
  Status ancestors(const std::string& p) const {
    std::string at;
    std::vector<std::string> chain;
    for (std::size_t i = 1; i < p.size(); ++i) if (p[i] == '/') chain.push_back(p.substr(0, i));
    for (const auto& a : chain) {
      auto it = entries.find(a);
      if (it == entries.end()) return Status::NotFound;
      if (!it->second.dir) return Status::NotADirectory;
    }
    return Status::Ok;
  }
  Status mkdir(const std::string& p) {
    Status s = ancestors(p);
    if (s != Status::Ok) return s;
    if (entries.count(p)) return Status::AlreadyExists;
    entries[p] = Entry{};
    return Status::Ok;
  }
  Status write(const std::string& p, const std::string& c) {
    Status s = ancestors(p);
    if (s != Status::Ok) return s;
    auto it = entries.find(p);
    if (it != entries.end() && it->second.dir) return Status::IsADirectory;
    entries[p] = Entry{false, c};
    return Status::Ok;
  }
  Status read(const std::string& p, std::string& out) const {
    Status s = ancestors(p);
    if (s != Status::Ok) return s;
    auto it = entries.find(p);
    if (it == entries.end()) return Status::NotFound;
    if (it->second.dir) return Status::IsADirectory;
    out = it->second.content;
    return Status::Ok;
  }
  Status remove(const std::string& p) {
    Status s = ancestors(p);
    if (s != Status::Ok) return s;
    auto it = entries.find(p);
    if (it == entries.end()) return Status::NotFound;
    if (it->second.dir && hasBelow(p)) return Status::NotEmpty;
    entries.erase(it);
    return Status::Ok;
  }
  Status list(const std::string& p, std::string& out) const {
    Status s = ancestors(p);
    if (s != Status::Ok) return s;
    auto it = entries.find(p);
    if (it == entries.end()) return Status::NotFound;
    if (!it->second.dir) return Status::NotADirectory;
    std::set<std::string> names;
    for (const auto& e : entries) if (e.first != "/" && parentOf(e.first) == p) names.insert(nameOf(e.first));
    out.clear();
    for (const auto& n : names) out += (out.empty() ? "" : ",") + n;
    return Status::Ok;
  }
  Status size(const std::string& p, Sz& out) const {
    Status s = ancestors(p);
    if (s != Status::Ok) return s;
    auto it = entries.find(p);
    if (it == entries.end()) return Status::NotFound;
    out = 0;
    for (const auto& e : entries) {
      const bool below = p == "/" || e.first == p || (e.first.size() > p.size() + 1 && e.first.compare(0, p.size() + 1, p + "/") == 0);
      if (below && !e.second.dir) out += e.second.content.size();
    }
    return Status::Ok;
  }
  Status move(const std::string& a, const std::string& b) {
    if (b.size() > a.size() + 1 && b.compare(0, a.size() + 1, a + "/") == 0) return Status::InvalidPath;
    Status s = ancestors(a);
    if (s != Status::Ok) return s;
    if (!entries.count(a)) return Status::NotFound;
    s = ancestors(b);
    if (s != Status::Ok) return s;
    if (entries.count(b)) return Status::AlreadyExists;
    std::map<std::string, Entry> moved;
    for (auto it = entries.begin(); it != entries.end();) {
      if (it->first == a || (it->first.size() > a.size() + 1 && it->first.compare(0, a.size() + 1, a + "/") == 0)) {
        moved[b + it->first.substr(a.size())] = it->second;
        it = entries.erase(it);
      } else {
        ++it;
      }
    }
    for (auto& m : moved) entries[m.first] = m.second;
    return Status::Ok;
  }
};
}  // namespace
