You are writing the booking core for a regional car-rental company. A customer reserves a kind of car for a stretch of time, collects a real car at the counter, and brings it back. The company must never promise a car it cannot hand over.

What you know so far:

- The fleet is split into categories (compact, SUV, van), each with a price per day. A category has several individual cars, each with a licence plate.
- A customer reserves a category and a time, not a particular car. The counter assigns a real car when the customer turns up.
- Customers change their minds, and some bring the car back early or late.
- The system must not read the time itself: the hour arrives through a `Clock` the caller supplies, so a test (or a replay) controls it.

Your task: design and implement it behind the `rental::Rentals` interface in `api.h`. The hidden tests call only that interface. Ask the interviewer questions first: the brief is deliberately incomplete, and "is a car that is booked for tomorrow free today?" is where most first drafts go wrong.

## Requirements
Functional: car categories with a price per started day, individual cars with plates, and a clock-driven lifecycle: a customer **reserves** a category for a period, **picks up** a real car, and **returns** it. Reserving promises one car for the whole period or nothing and returns an id and the total. Cancelling is possible until the car is collected. Time arrives through an injected `Clock` as a whole number of hours. A rental is the half-open range of hours `[pickup, dropoff)`, one to 720 hours, and costs the daily rate times `ceil(hours / 24)`. Checks run in a fixed order for every operation (documented in `api.h`). Hidden until asked: whether the drop-off hour is held, whether sequential rentals "add up", what pickup does when the cars are late, and what an early or late return does. Non-goals: payment, insurance, maintenance, branches, thread safety (discussed), persistence.

**Change Storm 1, late fees:** `makeLateFeeRentals(clock, grace, percent)`. After the grace hours, each late hour costs a percentage of the category's daily rate, added to the total, rounded down once. Revealable by asking what happens when cars come back late.

**Change Storm 2, rotation:** `makeRotatingRentals(clock, grace, percent)` hands out the car that has been idle longest; never-rented cars first; ties go to the lower plate. Revealable by asking whether it matters which free car is handed out.

## Reference design
- `TimeSpan` is the half-open range of hours: validity, overlap, early ending and the started-day count. It knows nothing about cars or money.
- `Schedule` is the promises: reservation id, category and span. Its one question is the busiest hour of a span, answered by an event sweep (ends before starts at the same hour).
- `Fleet` is the physical cars: category, out or not, and when each last came back.
- `Bookings` issues ids and keeps customer, category, span, total and the plate once collected. A removed record looks never issued.
- `Tariff` knows what each category costs and prices a span.
- `LateFee` is a Strategy (`NoLateFee`, `GraceThenPercent`) and `CarChooser` is a Strategy (`LowestPlate`, `LongestIdle`).
- `RentalsImpl` is the facade: it validates in the documented order and sequences the collaborators. It holds no rule of its own about hours, prices, fees or which car goes out.

The central decision is the split between **promises** (`Schedule`, counts) and **cars** (`Fleet`, plates). They can disagree for a while, and the design says so openly: a late car makes `pickUp` fail with `NoCarReady` even though the reservation was valid.

**Storm 1 in the reference:** `GraceThenPercent` is a new class; `returnCar` asks `LateFee::extra` and adds it. No existing class changes behaviour. **Storm 2 in the reference:** `LongestIdle` is a new class. The fleet already records when each car came back, which is the one thing Storm 2 needs; the honest cost is that `Fleet` was built for it in advance, and the editorial would be lying if it said it was a surprise for a design that only tracked "out or not".

## Alternatives
- **Assign a car at reservation time** (a list of intervals per car, first-fit). It feels natural and is a trap: online first-fit interval assignment can refuse a request that a count-based check accepts, because earlier choices fragment the cars. Keeping the promise as a count and assigning at the counter avoids the problem, at the price of the late-car failure above.
- **Count overlapping reservations** is the first thing most candidates write. It answers "how many reservations touch this range" and rejects sequential bookings that never needed two cars at once. The busiest hour is the right question.
- **An array of hours** works for a fixed horizon. The sweep over the relevant reservations needs no horizon and costs O(reservations in the category) per request, which is fine here and is the first thing to index at scale.
- **A State pattern per reservation** (Reserved, PickedUp, Returned, Cancelled) is the textbook shape. The only states here are "promise exists", "car collected" and "spent", so a record with a plate and an erase on completion is enough; real states would pay for themselves with inspections, damage and disputes, which are in the follow-ups.
- **A cron job that releases no-shows** looks tempting. Deriving "lapsed" from the clock and the span needs no timer, no thread and no stale state.
- **Maintenance, branches, one-way rentals** each break the "interchangeable cars" assumption. Saying which class changes for each is stronger than building any of them.

## Trade-offs
Counting per category keeps reserving honest about what was promised and cheap to reason about; it gives up the ability to promise a particular car. Splitting `Schedule` from `Fleet` makes the late-return failure visible instead of hiding it in one class that tries to be consistent about both. Putting the fee and the car choice behind Strategies costs two small interfaces now and makes both storms additive. Computing everything from the injected clock costs a parameter on a few calls and removes timers entirely.

## What breaks at 10x
At 10x the cars, nothing changes: categories are independent, so shard by branch and category. At 10x the traffic on one category, the per-category lock is the hot spot and the O(reservations) sweep per request starts to matter: keep the schedule as per-hour counters or an interval tree, and serve search from a stale read model. Lapsed no-shows accumulate forever in this in-memory version and need a sweeper. Reserving needs an idempotency key before retries are safe.

## Level signals
- **SDE2:** the half-open range stated and used consistently, started days computed correctly, a failed reserve that changes nothing, a cancel that frees only its own slot and spends the id, checks in the documented order.
- **Senior:** asks about the drop-off hour, sequential rentals and late cars before coding; separates promises from physical cars and says what can disagree; keeps span, schedule, fleet, bookings and tariff as small classes; makes the fee and the car choice Strategies when the change arrives; names the lock per category.
- **Staff:** explains why per-car first-fit assignment is a trap, treats maintenance and branches as changes of the interchangeability assumption, moves correctness into a conditional write in a shared store with idempotency, separates search from reservation, and quantifies overbooking against no-shows.

// Public API for the Car rental problem. The hidden tests only use what is declared here.
// You implement rental::makeRentals() (in any of your .cpp files); everything behind it is your design.
#include <memory>
#include <string>

namespace rental {

// A source of the current time, as a whole number of hours. The system must read the time only through this interface.
class Clock {
 public:
  virtual ~Clock() = default;
  virtual long long nowHours() const = 0;
};

using ReservationId = long long;
constexpr ReservationId kNoReservation = 0;  // ids that are issued are always positive and never reused
using Money = long long;                     // whole cents

constexpr Money kMaxDailyRate = 100000;  // cents per started day
constexpr int kMaxHours = 720;           // longest single rental: 30 days

enum class Status {
  Ok,
  UnknownCategory,     // no such car category
  InvalidRequest,      // empty customer, a rental of no hours or fewer, or more than kMaxHours hours
  InPast,              // the rental would start before now
  NoneAvailable,       // at some hour of the rental every car of the category is already committed
  UnknownReservation,  // never issued, or already cancelled or returned
  WrongCustomer,       // the reservation belongs to someone else
  AlreadyPickedUp,     // the customer already has the car
  NotPickedUp,         // there is no car to bring back yet
  TooEarly,            // now is before the pickup hour
  Lapsed,              // now is at or after the drop-off hour, and the car was never collected
  NoCarReady,          // every car of the category is out with somebody
};

struct ReserveResult {
  Status status = Status::Ok;
  ReservationId id = kNoReservation;  // kNoReservation unless status is Ok
  Money total = 0;                    // 0 unless status is Ok
};

struct PickUpResult {
  Status status = Status::Ok;
  std::string plate;  // empty unless status is Ok
};

struct ReturnResult {
  Status status = Status::Ok;
  Money charge = 0;  // what the customer pays in the end; 0 unless status is Ok
};

// Hours are whole numbers. A rental from `pickup` to `dropoff` occupies the hours pickup, pickup+1, ..., dropoff-1:
// the drop-off hour itself is free, so one customer may bring a car back at the hour another collects it.
class Rentals {
 public:
  virtual ~Rentals() = default;

  // Adds a car category with a price per STARTED day (1..kMaxDailyRate). Returns false, changing nothing, when the
  // name is empty or taken or the rate is out of range.
  virtual bool addCategory(const std::string& category, Money dailyRate) = 0;

  // Adds one car, identified by its plate, to a category. Returns false, changing nothing, for an empty plate, a plate
  // that exists in any category, or an unknown category. Cars can be added at any time.
  virtual bool addCar(const std::string& plate, const std::string& category) = 0;

  // Promises one car of the category for the whole rental, or nothing. The customer is not given a particular car yet.
  // Checks run in this order, and the first failure is returned with nothing changed: UnknownCategory,
  // InvalidRequest, InPast (pickup < now; collecting this very hour is fine), NoneAvailable. The total is the daily
  // rate times the number of STARTED days: ceil(hours / 24).
  virtual ReserveResult reserve(const std::string& customer, const std::string& category, long long pickup,
                                long long dropoff) = 0;

  // Gives the promise back and spends the id. Failures, in this order: UnknownReservation, WrongCustomer,
  // AlreadyPickedUp. A failed call changes nothing.
  virtual Status cancel(ReservationId id, const std::string& customer) = 0;

  // Hands over a physical car of the reserved category: the free car with the LOWEST plate (by string comparison).
  // Failures, in this order: UnknownReservation, WrongCustomer, AlreadyPickedUp, TooEarly (now < pickup),
  // Lapsed (now >= dropoff), NoCarReady (every car of the category is out). A failed call changes nothing, so
  // NoCarReady can be retried later. A car that is out is free again only when it is returned.
  virtual PickUpResult pickUp(ReservationId id, const std::string& customer) = 0;

  // Takes the car back and spends the id. Failures, in this order: UnknownReservation, WrongCustomer, NotPickedUp.
  // The charge is the total the reservation was given. A car brought back before the drop-off hour frees the rest
  // of its hours for other reservations; a car that is returned late stays out until it is returned.
  virtual ReturnResult returnCar(ReservationId id, const std::string& customer) = 0;

  // How many more reservations of the category could be made for exactly this rental: the number of cars minus the
  // busiest hour of the rental. 0 for an unknown category or a rental that is not valid. It ignores now.
  virtual int available(const std::string& category, long long pickup, long long dropoff) const = 0;
};

// Returns nullptr when the clock is null.
std::unique_ptr<Rentals> makeRentals(std::shared_ptr<Clock> clock);

}  // namespace rental

  struct Live {
    rental::ReservationId id;
    long long from;
    long long to;
  };
  std::vector<Live> live;
  unsigned seed = 12345;
  auto next = [&seed](unsigned bound) {
    seed = seed * 1103515245u + 12345u;
    return (seed >> 16) % bound;
  };
  for (int step = 0; step < 400; ++step) {

      const std::size_t pick = next(static_cast<unsigned>(live.size()));
      EXPECT_TRUE(f.rentals->cancel(live[pick].id, "u") == Status::Ok);
      for (long long h = live[pick].from; h < live[pick].to; ++h) --held[static_cast<std::size_t>(h)];
      live.erase(live.begin() + static_cast<long>(pick));
      continue;
    }
    const long long from = 100 + next(60);
    const long long to = from + 1 + next(15);
    bool fits = true;
    int busiest = 0;
    for (long long h = from; h < to; ++h) {
      busiest = std::max(busiest, held[static_cast<std::size_t>(h)]);
      if (held[static_cast<std::size_t>(h)] >= 2) fits = false;
    }
    EXPECT_EQ(f.rentals->available("compact", from, to), 2 - busiest);
    const auto r = f.reserve("u", "compact", from, to);
    EXPECT_TRUE((r.status == Status::Ok) == fits);
    if (r.status == Status::Ok) {
      live.push_back({r.id, from, to});
      for (long long h = from; h < to; ++h) ++held[static_cast<std::size_t>(h)];
    }
  }

class CarChooser {
 public:
  virtual ~CarChooser() = default;
  // `idle` is never empty.
  virtual std::string choose(const std::vector<IdleCar>& idle) const = 0;
};

class LowestPlate : public CarChooser {
 public:
  std::string choose(const std::vector<IdleCar>& idle) const override {
    return std::min_element(idle.begin(), idle.end(), [](const IdleCar& a, const IdleCar& b) { return a.plate < b.plate; })
        ->plate;
  }
};

// The car that has waited longest. Cars never returned have waited forever; ties go to the lower plate.
class LongestIdle : public CarChooser {
 public:
  std::string choose(const std::vector<IdleCar>& idle) const override {
    return std::min_element(idle.begin(), idle.end(), &LongestIdle::waitsLess)->plate;
  }

 private:
  static bool waitsLess(const IdleCar& a, const IdleCar& b) {
    if (a.everReturned != b.everReturned) return !a.everReturned;
    if (a.everReturned && a.returnedAt != b.returnedAt) return a.returnedAt < b.returnedAt;
    return a.plate < b.plate;
  }
};

// The promises made, per category: which hours each reservation holds a car. It answers one question, "how many cars
// are committed at the busiest hour of this span", and knows nothing about which physical car is which.
class Schedule {
 public:
  void add(rental::ReservationId id, const std::string& category, const TimeSpan& span) {
    entries_[id] = Entry{category, span};
  }
  void remove(rental::ReservationId id) { entries_.erase(id); }

  // A car came back early: the hours after `hour` are free again.
  void endEarly(rental::ReservationId id, long long hour) {
    const auto it = entries_.find(id);
    if (it == entries_.end()) return;
    it->second.span = it->second.span.endedAt(hour);
    if (it->second.span.isEmpty()) entries_.erase(it);
  }

  // The most reservations of the category that hold a car at the same hour inside `span`.
  int peak(const std::string& category, const TimeSpan& span) const {
    std::vector<std::pair<long long, int>> changes;  // +1 where a hold starts, -1 where it ends
    int holding = 0;
    for (const auto& [id, entry] : entries_) {
      if (entry.category != category || !entry.span.overlaps(span)) continue;
      const long long start = std::max(entry.span.from(), span.from());
      const long long end = std::min(entry.span.to(), span.to());
      if (start == span.from()) ++holding;
      else changes.emplace_back(start, +1);
      if (end < span.to()) changes.emplace_back(end, -1);
    }
    std::sort(changes.begin(), changes.end());  // at the same hour a -1 sorts before a +1: the car is back first
    int busiest = holding;
    for (const auto& change : changes) {
      holding += change.second;
      busiest = std::max(busiest, holding);
    }
    return busiest;
  }

 private:
  struct Entry {
    std::string category;
    TimeSpan span{0, 0};
  };
  std::map<rental::ReservationId, Entry> entries_;
};
